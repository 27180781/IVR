# פריסה

שני מסלולים: **פריסה ראשונה** על שרת חדש, ו**פריסות שוטפות** מכאן והלאה.

---

# חלק א׳ — פריסה ראשונה על דרופלט חדש

## 1. יצירת הדרופלט

| הגדרה | בחירה | למה |
|-------|--------|-----|
| Image | Ubuntu 24.04 LTS | מגיע עם Asterisk 20 LTS במאגר |
| Plan | Basic, 2 vCPU / 2GB | מספיק לעשרות שיחות במקביל |
| Region | Frankfurt (fra1) או Amsterdam (ams3) | הכי קרוב לישראל מבין אזורי DO |
| Authentication | SSH key | אל תשתמשו בסיסמה על שרת SIP |

**IPv6** — אפשר להשאיר כבוי. טוויליו מדברת IPv4 בטראנקים.

## 2. שאלת ה־Reserved IP

זו הנקודה שהכי קל להיכשל בה בדיגיטל אושן.

ה־IP של הדרופלט מוצמד אליו, ואם תשמידו ותקימו מחדש — הוא ישתנה, ותצטרכו
לעדכן את טוויליו. Reserved IP פותר את זה, **אבל** דיגיטל אושן מממשת אותו
כ־NAT 1:1: הדרופלט לא רואה את הכתובת על הממשק שלו, ותעבורה יוצאת עלולה
לצאת דרך ה־IP הרגיל שלו. עבור SIP זה קטלני — טוויליו שולחת ל־IP אחד ומקבלת
תשובות מ־IP אחר, והשיחות נופלות בלי הסבר.

**ההמלצה שלי לשלב הזה: השתמשו ב־IP הרגיל של הדרופלט ואל תשמידו אותו.**
פשוט, ועובד. אם בכל זאת תרצו Reserved IP, העבירו את הכתובת הציבורית
במפורש:

```bash
./scripts/bootstrap-server.sh --public-ip <RESERVED_IP>
```

כדי שאסטריסק יפרסם את הכתובת שטוויליו באמת רואה, ואמתו עם שיחת בדיקה
לפני שעולים לאוויר.

## 3. Cloud Firewall

הסקריפט מגדיר `ufw` על השרת עצמו. אם תצרפו בנוסף Cloud Firewall של דיגיטל
אושן — הוא פועל **לפני** הדרופלט, וחייב לאפשר את אותם פורטים, אחרת שום
דבר לא יגיע:

| Type | Protocol | Ports | Sources |
|------|----------|-------|---------|
| SSH | TCP | 22 | ה־IP שלכם |
| SIP | UDP | 5060 | טווחי הסיגנלינג של טוויליו |
| RTP | UDP | 10000-20000 | `168.86.128.0/18` |

## 4. ההרצה

```bash
ssh root@<droplet-ip>
apt update && apt install -y git
git clone https://github.com/27180781/IVR.git /opt/ivr
cd /opt/ivr
./scripts/bootstrap-server.sh
```

הסקריפט מטפל בהכל: חומת אש, אסטריסק, Node, יצירת סיסמת ARI אקראית
(ומסנכרן אותה בין `.env` ל־`ari.conf`), פריסת הקונפיג, בניית האפליקציה,
יצירת משתמש השירות והתקנת יחידת systemd. **בטוח להריץ שוב** — הוא לא דורס
`.env` קיים.

בסיום הוא מדפיס בדיוק מה נשאר: להקליט הודעות, ולהצביע את טוויליו ל־IP.

# חלק ב׳ — פריסות שוטפות

## למה זה לא כמו לפרוס אתר

הפעלה מחדש של האפליקציה באמצע שיחה מנתקת את המתקשר. לכן `deploy.sh` בנוי
סביב ארבע תכונות, ולא רק `git pull && restart`:

1. **בונה לפני שהוא עוצר משהו.** בנייה שנכשלת לא מורידה את הקו — התהליך
   הישן ממשיך לענות.
2. **מנקז שיחות.** ב־SIGTERM האפליקציה מפסיקה לקבל שיחות חדשות (הן חוזרות
   ל־dialplan ושומעות "המערכת אינה זמינה"), ומחכה שהשיחות הפעילות יסתיימו
   באופן טבעי. לכן פריסה יכולה לקחת דקה־שתיים בשעת עומס — וזה הטרייד־אוף
   הנכון.
3. **מאמת את הדבר הנכון.** לא "האם התהליך רץ" אלא **האם אסטריסק קיבל אותו
   בחזרה כאפליקציית Stasis**. תהליך שרץ אבל לא נרשם נראה בריא לחלוטין
   ל־systemd, ולא עונה לאף שיחה.
4. **מתגלגל אחורה.** אם האימות נכשל — חוזר לקומיט הקודם, בונה ומפעיל שוב.
   קו טלפון שמריץ קוד מלפני שבוע עדיף על קו טלפון שלא עונה.

## ידנית

```bash
ssh root@<droplet-ip>
cd /opt/ivr && sudo ./scripts/deploy.sh
```

## אוטומטית מגיטהאב

`.github/workflows/deploy.yml` פורס בכל מיזוג ל־`main`, וגם ידנית מלשונית
Actions. תהליך העבודה: הוא **קודם בונה ובודק טיפוסים ב־CI**, ורק אם זה עבר
מתחבר ב־SSH ומריץ את `deploy.sh`.

### הכנת משתמש פריסה ייעודי

אל תתנו לגיטהאב מפתח root. צרו משתמש עם sudo מוגבל לסקריפט אחד בלבד:

```bash
sudo adduser --disabled-password --gecos "" deploy
sudo mkdir -p /home/deploy/.ssh && sudo chmod 700 /home/deploy/.ssh

# מפתח ייעודי לפריסות בלבד
ssh-keygen -t ed25519 -f ~/deploy_key -N "" -C "github-actions-deploy"
sudo tee /home/deploy/.ssh/authorized_keys < ~/deploy_key.pub
sudo chown -R deploy:deploy /home/deploy/.ssh
sudo chmod 600 /home/deploy/.ssh/authorized_keys

# sudo רק לסקריפט הפריסה, בלי סיסמה
echo 'deploy ALL=(root) NOPASSWD: /opt/ivr/scripts/deploy.sh' \
  | sudo tee /etc/sudoers.d/ivr-deploy
sudo chmod 440 /etc/sudoers.d/ivr-deploy
sudo visudo -c        # אימות שהתחביר תקין

# המשתמש צריך גם להיות מסוגל לכתוב לצ'קאאוט
sudo usermod -aG ivr deploy
```

### הגדרת הסודות בגיטהאב

Settings → Secrets and variables → Actions → New repository secret:

| Secret | ערך |
|--------|-----|
| `DEPLOY_HOST` | ה־IP הציבורי של הדרופלט |
| `DEPLOY_USER` | `deploy` |
| `DEPLOY_SSH_KEY` | תוכן `~/deploy_key` — **המפתח הפרטי**, כל הקובץ כולל שורות ה־BEGIN/END |
| `DEPLOY_PATH` | `/opt/ivr` |

ואז מחקו את המפתח הפרטי מהמכונה שיצרה אותו:

```bash
rm ~/deploy_key ~/deploy_key.pub
```

### חלופה: משיכה במקום דחיפה

אם לא נוח לכם להחזיק מפתח SSH בגיטהאב, אפשר להפוך את הכיוון — טיימר של
systemd שמריץ `deploy.sh` כל כמה דקות. יתרון: אין גישה נכנסת מגיטהאב בכלל.
חיסרון: פריסה מתעכבת עד הטיק הבא.

## אחרי כל פריסה

```bash
journalctl -u ivr-app -f
sudo asterisk -rx 'ari show apps'      # חייב להראות ivr-app
```

`deploy.sh` כבר בודק את שניהם ונכשל אם משהו לא במקום — אבל אחרי שינוי
משמעותי, שיחת בדיקה אמיתית שווה יותר מכל לוג.
