# לוח הבקרה

עמוד אחד שמראה מה קורה במערכת — שיחות פעילות בזמן אמת, היסטוריית שיחות
עם המסלול המלא של כל אחת, ויומן חי — במקום SSH.

```
https://your-domain.com
```

## מה יש בו

**שיחות פעילות כעת** — מי מדבר עכשיו, באיזה שלב בתפריט הוא נמצא, וכמה זמן.
מתעדכן תוך כדי השיחה.

**שיחות אחרונות** — מתי, ממי, כמה זמן, איך הסתיימה, איזו הזמנה נשלפה,
ו**המסלול המלא** שהמתקשר עבר: `welcome ← mainMenu ← askReference ← …`.
המסלול הוא הכלי הכי שימושי כאן — הוא מראה בדיוק איפה אנשים ננטשים.

**יומן חי** — אותן שורות שהיו מופיעות ב‑`journalctl -u ivr-app -f`.

**מדדים** — שיחות ב‑24 שעות, אחוז ההשלמה, משך ממוצע.

הכל דרך Server-Sent Events: הדפדפן לא מרענן, השרת דוחף.

## התקנה

### 1. רשומת DNS

צרו רשומת **A** לדומיין שבחרתם, שמצביעה ל‑IP של השרת. חכו שהיא תתפשט —
בדקו עם `dig +short A your-domain.com`.

### 2. הרצה

```bash
cd /opt/ivr
sudo ./scripts/setup-web.sh your-domain.com
```

הסקריפט **בודק קודם שה‑DNS מצביע לשרת הזה** ומסרב אחרת. זה לא קפדנות
מיותרת: Let's Encrypt מאמת בכך שהוא מתחבר לכתובת שברשומה, ואם היא מצביעה
למקום אחר — הנפקת התעודה נכשלת עם שגיאה שלא מסבירה כמעט כלום.

אחריו: התקנת Caddy, HTTPS אוטומטי, פתיחת 80/443, וסיסמה שנוצרת אם אין.
בסיום הוא מדפיס את שם המשתמש והסיסמה.

> אם מוצמד **Cloud Firewall** של דיגיטל אושן — הוא חייב להתיר 80 ו‑443,
> אחרת ה‑ufw שהסקריפט הגדיר לא רלוונטי.

## אבטחה

**הדשבורד מכיל מספרי טלפון של מתקשרים.** זה מידע אישי, והוא מעצב את כל
ההחלטות כאן:

| החלטה | למה |
|--------|-----|
| ללא `WEB_PASSWORD` הדשבורד **לא עולה** | ברירת מחדל פתוחה היא דליפת מידע. נכשל סגור. |
| מאזין על `127.0.0.1` בלבד | חשיפה ישירה תגיש את הנתונים ב‑HTTP גלוי |
| HTTPS דרך Caddy | Basic Auth על HTTP שולח את הסיסמה בטקסט קריא |
| `X-Robots-Tag: noindex` | עמוד כזה לא אמור להופיע בגוגל |
| השוואת סיסמה בזמן קבוע | זמן תגובה לא ידלוף את הסיסמה |

החלפת סיסמה:
```bash
sed -i 's/^WEB_PASSWORD=.*/WEB_PASSWORD=<new>/' /opt/ivr/.env
systemctl restart ivr-app
```

**כיבוי מוחלט:** `WEB_ENABLED=false` ב‑`.env` והפעלה מחדש.

## הערות תכנון

**הדשבורד רץ בתוך אפליקציית ה‑IVR, ולא יכול להפיל אותה.** כל בקשה עטופה,
שגיאת רינדור נרשמת ולא מתפשטת, ואם השרת לא מצליח לעלות — הטלפוניה ממשיכה
כרגיל. התהליך הזה קיים כדי לענות לשיחות; עמוד ניהול הוא לא סיבה מספקת
להפסיק.

**הכל בזיכרון וחסום בגודל.** היומן הוא ring buffer של 500 שורות
(`WEB_LOG_BUFFER`), ולוג השיחות נקרא רק מהזנב שלו. תהליך שרץ חודשים לא
יכול לגדול לתוך המבנים האלה.

**אין תלות חיצונית בעמוד.** אין CDN, אין פונטים חיצוניים, CSP מהודק. הוא
ייטען גם אם חצי מהאינטרנט למטה.

**מה שאין:** אין כתיבה. הדשבורד קורא בלבד — אי אפשר לשנות ממנו את התפריט,
לנתק שיחה או לגעת בקונפיג. זו החלטה מכוונת לשלב הזה.
